# FundTrace 面试讲述

定位：Data Product + Explainable Quantitative Intelligence。以下个人角色表述基于项目负责人的陈述；面试时只讲自己实际负责的决策与工作。

## 1 分钟介绍

**背景：**基金持仓披露是低频快照，但研究员需要持续观察行业配置变化。两次披露之间存在信息空窗。

**我的角色：**我在实习期间主导 FundTrace 的产品设计，把这个问题定义为“帮助研究员发现需要进一步验证的行业暴露线索”。

**产品设计：**我将基金输入、数据处理、模型分析、趋势图、可信度诊断和报告输出串成完整流程，并把拟合质量与结果可信度分开展示。

**技术方案：**通过模拟行业组合、滚动窗口、时间衰减和非负 Lasso，从基金净值与行业收益中估计周频行业暴露，使用 React 和 FastAPI 提供操作界面。

**价值：**161005 的离线分析与 Dashboard 已实际跑通。更重要的是，产品能在拟合较好但结果偏离明显时提示谨慎参考。当前证明了流程可用，还没有证明研究效率或投资收益提升。

## 3 分钟介绍

**为什么做。**我观察到基金研究有一个时间粒度不匹配的问题：净值每天变化，持仓披露却是低频快照。研究员可以看到基金涨跌，但两次披露之间的行业配置变化不容易直接观察。因此我没有把目标设成实时还原持仓，而是补充可复核的研究线索。

**怎么设计。**我先明确用户任务：输入一只基金，看到当前隐含暴露和近期变化，再判断哪些变化值得核查。因此流程从基金代码开始，经过数据清洗、行业映射、时间对齐、模型计算，进入暴露曲线和诊断页，最后允许导出结果。React 负责交互，FastAPI 组织任务和结果，Python 完成数据与模型计算。公开仓库不附研究数据，面试用真实历史截图解释产品。

**为什么这样选模型。**基金收益可以近似看作不同产业收益的组合。先用披露构建季度模拟行业组合，再用滚动回归观察更短时间尺度的变化。120 个交易日窗口在响应速度与样本稳定性之间取舍；40 日半衰期给近期信息更高权重。非负约束符合所研究的多头权益暴露场景，Lasso 减少不必要的行业系数。但行业相关性和遗漏资产仍会让结果不唯一。

**遇到的问题与解决。**关键问题是拟合好不等于持仓推断可信。示例最新窗口 R² 约 0.831，但暴露总量和结构存在明显偏离。如果界面只显示“模型质量 A”，用户容易过度信任。V1.4 因此将模型质量与结果可信度分成两个判断，当前示例显示 A 和 C，并展示风险原因。另一个问题是复现与现场抓数不稳定：开发环境已验证本地数据离线运行；公开展示采用真实截图与方法文档，不依赖面试现场下载数据。

**产品价值与下一步。**我认为价值是把数据、算法与不确定性组织成一个可操作的研究流程。当前已验证单基金的工程流程，不能据此宣称持仓准确率或业务增益。下一步应使用完整持仓、实际公告日期和多基金样本外测试验证结果，再通过研究员任务实验衡量耗时、有效线索率和误报。这体现了我的产品判断：模型输出要服务用户决策，评价和边界本身也是产品的一部分。

## 面试追问与回答要点

| # | 问题 | 回答要点 |
|---|---|---|
| 1 | 谁会用？ | 基金研究员、基金筛选和组合研究人员；尚无正式用户规模或机构上线证据。 |
| 2 | 具体使用场景？ | 定期复盘基金，观察行业偏离，再结合披露和其他资料核查。 |
| 3 | 为什么行业需要？ | 净值变化与持仓披露的频率不匹配，产生持续研究的信息空窗。 |
| 4 | 核心产品需求是什么？ | 看变化、判断能否参考、知道下一步查什么；不是承诺真实仓位。 |
| 5 | 为什么不用普通回归？ | 无约束回归可能出现难以解释的负权重和不稳定系数；约束符合所选场景，但不能证明普遍优于 OLS。 |
| 6 | 为什么用 Lasso？ | L1 惩罚有助于压缩不必要的系数；相关行业之间仍可能发生替代，需要稳定性检查。没有完成全面算法优劣对比。 |
| 7 | 为什么非负？ | 适合多头权益基金的行业暴露解释；不应直接推广到对冲和复杂衍生品策略。 |
| 8 | 滚动窗口为什么是 120 日？ | 当前默认折中：短窗响应快但噪声大，长窗稳定但滞后；它不是已证明的全市场最优值。 |
| 9 | 时间衰减有什么作用？ | 40 日半衰期降低旧样本影响；也可能提高对近期噪声的敏感度。 |
| 10 | 模拟行业组合是什么？ | 以披露为基础补全季度行业结构的估计，不是完整持仓真值。 |
| 11 | 总暴露上限做什么？ | 限制不可解释的权益暴露总量；当前保留稳定版 legacy 规则，没有合入 B2 实验。 |
| 12 | 为什么是周频？ | 面向周期研究与图表可读性，控制日频噪声；不是把周频标签当新增信息。 |
| 13 | R² 0.831 代表什么？ | 表示该窗口内收益拟合程度，不是持仓正确比例，也不是未来收益保证。 |
| 14 | 为什么模型 A、可信度 C？ | 拟合较好，但隐含暴露与披露基座的总量和结构偏离较大。两个等级回答不同问题。 |
| 15 | 如何验证真实准确性？ | 用完整持仓汇总、实际公告时点及多基金样本外检验；当前没有完成这些充分验证。 |
| 16 | 有前视偏差吗？ | 当前时间对齐与部分评分窗口仍有限制，不能宣称严格无前视。详见方法文档。 |
| 17 | 图上的区间是置信区间吗？ | 当前噪声带是启发式提示，不能当经过统计覆盖率校验的置信区间。 |
| 18 | 如何处理共线性？ | 正则化与约束可缓解部分问题，无法消除行业相关造成的多解；应做敏感性与稳定性分析。 |
| 19 | 如何验证产品价值？ | 设计同一研究任务的对照实验，记录耗时、有效线索率、误报及采纳率；这些还不是已取得的成果。 |
| 20 | 与 Wind 有何区别？ | 本项目是围绕行业暴露核查的一条分析流程，不是完整金融信息终端，没有证据支持替代 Wind。 |
| 21 | 为什么要做 Dashboard？ | 将参数、结果、风险和导出放在研究任务中，减少使用脚本的门槛；门槛降低幅度仍需用户实验。 |
| 22 | 为什么要报告风险？ | 用户会把精确数字误认为确定事实。风险提示帮助判断是否需要进一步核查。 |
| 23 | 离线 Demo 如何实现？ | 原开发环境使用已存在的本地历史数据并关闭数据更新；公开仓库只保留真实截图和源码。 |
| 24 | 为什么不公开研究数据？ | 展示产品与实现不需要分发全部数据；数据来源、许可和再分发权需要单独确认。 |
| 25 | clone 后能直接分析吗？ | 可以构建界面和运行不依赖研究数据的测试；完整 161005 分析需要自行准备有权使用的数据。 |
| 26 | 这里的 AI 是什么？ | 数据智能、自动化分析与可解释统计学习。产品不含 LLM、RAG、Agent，也不借这些概念包装。 |
| 27 | 你的贡献如何证明？ | 解释自己定义的需求、做过的取舍和评价设计，并结合源码、版本记录及真实页面；不把团队或工具贡献据为己有。 |
| 28 | 下一步优先做什么？ | 先完善真值、时点和样本外评价，再做用户任务验证；优先于增加新模型或更多炫目页面。 |

## 推荐展示的三个页面

1. **GitHub 首页 / Product**：业务问题、目标用户、用户流程。先解释为什么做。
2. **完整 Dashboard**：行业暴露、近期变化与趋势。说明研究员如何发现核查线索。
3. **Model diagnostics + 方法文档**：A / C 的区别、模型选择和可信度边界。用一个真实反例体现产品判断。

不要声称实时还原、92.5% 持仓准确率、投资收益提升、替代 Wind、完整开源即用服务或机构正式部署。
